# Implementation notes

How the code maps to [`design.md`](design.md), and where it adds to or departs from the
reviewed design. `design.md` has been updated with every row below; this file keeps the
reasoning per change.

## Layout

| Path | Role |
|---|---|
| `app.py`, `cdk.json` | Context validation (fail fast on missing, placeholder or malformed keys); `-c allowPlaceholders=true` for placeholder synth only |
| `stacks/acxdmem_writer_stack.py` | Work queue + DLQ, writer Lambda (Python), fetch step (Node.js), dedup table, alarms |
| `stacks/acxdmem_api_stack.py` | REST API, two REQUEST authorizers, read + ingest Lambdas, endpoint secrets, access logs, optional WAF |
| `src/acxd_memory/` | Shared Python: `identity`, `reader` (ported), `writer`, `dedup` (ported + segments), `acxd_transcript`, `acxd_strip`, `state_machine`, `metrics` |
| `lambdas/{authorizer,read,ingest,writer}/` | Python handlers |
| `lambdas/fetch/` | Node.js fetch step, `amazon-connect-acxd-sdk` 0.2.0 + `@aws-sdk/client-secrets-manager`, both pinned with a lockfile; Python Lambdas vendor `boto3` from a hash-locked `requirements.txt` (`make lock`) |
| `scripts/` | `bundle_lambdas.sh`, `provision_memory.sh` (D2 extraction override), `preflight.py` (read-only) |

## Additions and departures

| # | Design | Implementation | Why |
|---|---|---|---|
| N1 | §3.2 "Node.js fetch step"; §9 writer role reads the API key | Separate Lambda `acxdmem-fetch`, invoked synchronously by the writer with IAM (`lambda:InvokeFunction` on its exact ARN). Only the fetch role can read the ACXD API key secret | Keeps the Python writer free of the key; no resource policy or URL on the fetch function |
| N2 | §3.3 `clientToken` = segment key | `clientToken` = SHA-256 hex of the segment key | API reference gives no length/charset limit for `clientToken`; the raw key (~60 chars with `#`) is close to common 64-char token limits. Same key, same token |
| N3 | — | Segments over 100 turns are split into several `CreateEvent` calls (chunk 0 uses the segment token, chunk n `segment#n`); text over 100 000 chars is truncated | `CreateEvent` payload is limited to 100 entries and 100 000 chars per text (botocore model) |
| N4 | §9 context key `acxdApplicationId` (usage not specified) | Writer skips conversations whose `applicationId` differs (`SkipReason=application_mismatch`) | Cheap defence against writes for conversations of another app in the same workspace |
| N5 | §4 Lambda timeout 3 s | 4 s, 1.5 s shared budget for the two parallel namespace calls, botocore 1 attempt | Design review: 3 s left no headroom for a cold start inside the 5 s data request timeout |
| N6 | §3.2 backoff 60/120/300 s, worst case ~630 s | Backoff indexed by the re-queue count; with the cap of 6 the worst case is 120 s + 1 380 s of re-queue delays, every delay ≤ 900 s, retention 1 h (4 days since N19) | The message body carries one counter (`attempt`); the cap is the binding limit |
| N7 | §3.4 claim: new or stale pending | Also re-claimable: `failed` (released after a `CreateEvent` error) and `pending` with the same SQS `messageId` | Without it an SQS retry inside the 15-min window would be dropped as a duplicate and the segment lost |
| N8 | §3.2 "write the last 200 response" at the cap | Written only if the capped invocation itself got a 200; otherwise `TranscriptIncomplete` (seen before) or `TranscriptNeverIndexed`, then ack | The message carries watermark and count, not content |
| N9 | §6 secret `acxdmem-endpoint-secret` | Two secrets, one per route, with names generated by CloudFormation (they were `acxdmem-endpoint-secret-read` / `-write` until N19) | Per-route secrets (§6) |
| N10 | — | Request validator also requires header `x-acxdmem-secret` | CDK Nag APIG2 needs body and parameter validation |
| N11 | — | `cloudWatchRole: false`; `preflight.py` checks the account-level API Gateway CloudWatch role | Never changes an account-wide setting from the stack |
| N12 | §4.2 corpus | Corpus = retrieved records + `format_memory_context` string; raw token `<var>:NLX.Context\|` removed; stripping fails open (`MemoryStripSkipped`) | As designed; listed for review |
| N13 | — | Empty segment (nothing left after stripping) advances the watermark | The next exit must not reconsider those messages |
| N14 | — | Message timestamps parsed as ISO 8601 or epoch s/ms; unparseable inherits the previous value | Wire format not captured in the spike [U] |

## Security rules enforced by tests (`tests/test_stacks.py`)

- No `AWS::Lambda::Url`. No wildcard principal, except the CDK TLS-only `Deny` on the two
  queues (`aws:SecureTransport=false`, CDK Nag SQS4), which the test allows explicitly.
- Every `AWS::Lambda::Permission`: principal `apigateway.amazonaws.com`, `SourceArn` on this
  API; route permissions are `<api>/v1/POST/memory/<route>` (no stage wildcard);
  authorizer permissions `<api>/authorizers/<id>`. No permissions in the writer stack.
- Every method: `CUSTOM` authorization, its own REQUEST authorizer (header identity source,
  TTL 300 s), request validator. Authorizer Allow is scoped to the request's `methodArn` and
  only for its bound route (unit-tested).
- Request models: `additionalProperties: false`, per-field `maxLength`.
- No IAM `Resource: *`; AgentCore actions only on the memory ARN; writer gets
  `RetrieveMemoryRecords` only with `enableStripping`.
- CDK Nag AwsSolutions: no unsuppressed findings, with and without WAF/stripping.
  Suppressions: L1 (pinned runtimes), SMG4 (manual rotation), COG4 (header auth, no OAuth),
  APIG3 (only when WAF is off).
- REST API security policy `SecurityPolicy_TLS13_1_2_PFS_PQ_2025_09` with `STRICT` endpoint
  access mode; access logs carry `tlsVersion` and the caller's `sourceIp`, and no header,
  body or `validationErrorString` fields.
- Endpoint secrets have no fixed name (a destroy followed by a deploy would collide with
  the previous secret's recovery window).
- Work queue retention 4 days, DLQ retention longer, and a queue-age alarm far below the
  retention.
- Every Lambda logs in JSON and has an `Errors` alarm; the stage has a 5XX alarm and a 4XX
  rate alarm; the work queue has an age alarm; ten alarms, none with actions.
- No IAM `Resource` is `*` or ends in `:*` / `/*`, also inside lists; non-literal resources
  reference one specific resource.
- Every tracked source file carries the MIT-0 SPDX header (`tests/test_license_headers.py`).

## Live verification

Deployed and verified end to end; see [`e2e-verification.md`](e2e-verification.md). Results
for the items this section listed before the deploy:

- `GetConversation` timestamps are ISO 8601 UTC strings with milliseconds; ordering matched
  the conversation; watermark and `eventTimestamp` equal the last message. N14's epoch
  fallback was not needed.
- Cold start of the read route: 4.1-4.5 s at 256 MB (authorizer and read both cold) against
  the 5 s ACXD timeout. Fixed (N15).
- `appendToPrompt` override: one sample where the agent restated memory and the restated
  facts were not re-extracted (n=1). The 8-word stripping threshold is still untested
  (`enableStripping` off).
- API Gateway body validation with the content type ACXD sends: every live request passed.

| # | Change found live | Implementation |
|---|---|---|
| N15 | Double cold start close to the 5 s ACXD data request timeout | Customer-facing Lambdas (read, ingest, both authorizers) at 1024 MB; clients created during init; the authorizer also loads its secret during init, and a failure there is logged, not raised |
| N16 | `provision_memory.sh` failed right after creating the role (IAM propagation) | Retries `CreateMemory` on that one error |
| N17 | `preflight.py` ignored `-c` overrides | `-c key=value`, as with the CDK CLI |
| N18 | Sample greeting "welcome back" was shown to first-time customers | Neutral greeting on both read paths |
